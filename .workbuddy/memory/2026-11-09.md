## CW Trainer V2：修复电脑端两个问题（仅 C# 侧，固件未改）

用户边界：硬件部分（含 .ino 固件）先不要动，只改 Desktop 软件；实板在 COM7。

### 改动文件
- 新增 `Desktop/CWTrainer.Desktop/MorseDecoder.cs`
  - `MorseTable`（字符表）+ `MorseDecoder`（解码状态机）+ `MorseCommit`。
  - 时间单位由固件上报的元素时长推导（点=1、划=3），不再用界面 WPM 猜。
  - 字符/单词间隔阈值 2.0 / 6.0 单位，从“元素结束时刻”起算静音。
  - `PushElement` / `Tick` / `Reset` / `SetWpm`，纯逻辑、时间外部注入，可单测。
- `MainWindow.xaml.cs` 重写
  - 串口解析从 UI 线程移到 `DataReceived` 线程，事件时间戳在接收处取，避免 UI 卡顿破坏解码时序。
  - 解码定时器改为 `System.Threading.Timer`（20ms），心跳改为线程池 `Timer`（1s）。
  - 关闭窗口改为“先取消 + 异步 BYE 交接（等 BYE,BUZZER 确认，超时 900ms）+ 再关闭”。
  - 新增 `EmergencyHandoff()`，音频状态加锁，`_handshakeSource` 改用局部变量避免竞态。
- `App.xaml.cs`：`OnSessionEnding` / `DispatcherUnhandledException` / `ProcessExit` 均调用 `EmergencyHandoff()`。

### 已验证
- `dotnet build` 0 警告 0 错误。
- 临时控制台工程跑解码器时序测试：CQ / CQ CQ / SOS / HELLO / 5·25·15 WPM / ±25ms 抖动 / 字符间隔 4 单位 / 数字 全部通过。

### 实板发现（重要）
- COM7 上跑的固件**不是**仓库 HEAD 版本：它对每个收到的字节打印 `DBG_RX,<hex>` 和 `DBG_LINE,...`。
  该调试代码存在于历史提交 668337b / 884aa88，位于 `readSerialCommands()` 内，用 `Serial.print` 逐字节输出。
- 关闭串口后 COM7 无法再次打开（Windows 报“设备没有发挥作用”），必须物理 RST/重新插拔。
  与“关软件后硬件静音、只能 RST”的现象一致：调试输出把 USB CDC 写满 → `Serial.println` 阻塞 → `loop()` 停摆 → 6 秒失联回退永远不执行；同时 CDC 端点被拖死。
- 结论：问题 A 的首要疑因是板上那份带调试打印的固件，而不是仓库里的 HEAD 固件（HEAD 无 DBG 输出）。

### 待办
- 用户 RST 后，用 HEAD 固件复测“关软件 / 强杀进程 / 拔 USB”三种场景。
- 若 HEAD 仍复现，需要改固件（租约刷新 + 每周期重算输出），需用户授权。

## 收尾：音频设备选择 + 发布 + README

### 新增 AudioOutput.cs
- 音频从 PlaySound 换成 winmm `waveOut`，因为 PlaySound 只能走默认设备。
- 设备列表第 0 项是「跟随系统」（WAVE_MAPPER）；静音 4 秒释放设备，
  下次发声重新 open，WAVE_MAPPER 会重新解析默认设备 → 插拔耳机不用重启。
- 自管 WAVEHDR + 缓冲区（AllocHGlobal / PrepareHeader / Write / Reset），
  元素音带 3ms 淡入淡出；直键用 WHDR_BEGINLOOP/ENDLOOP 无缝循环 + Reset 停止。
- 打不开指定设备时自动退回 WAVE_MAPPER 并写日志。

### 踩到的坑（重要）
`WAVEOUTCAPS` 里 **szPname 在 dwSupport 之前**（16 字节头 + 64 字节名字 + 4 字节 dwSupport = 84）。
按头文件直觉写成 dwSupport 在前，读出来的设备名会整体左移 4 字节，变成 "igh Definition Audio Devi"。
MME 名字上限 32 字符，接近上限时补「…」。

### 界面调整
- 画布 1200×760 → 1200×800，顶栏 64 → 56，给「输出设备」留一行。
- 声音输出卡片：分段 → 输出设备 → 音调 → 音量。
