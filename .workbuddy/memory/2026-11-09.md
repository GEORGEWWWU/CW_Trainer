## CW Trainer V2：修复电脑端两个问题（仅 C# 侧，固件未改）

用户边界：硬件部分（含 .ino 固件）先不要动，只改 Desktop 软件；实板在 COM7。

### 改动文件
- 新增 `Desktop/CWTrainer.Desktop/MorseDecoder.cs`
  - `MorseTable`（字符表）+ `MorseDecoder`（解码状态机）+ `MorseCommit`。
  - 时间单位由固件上报的元素时长推导（点=1、划=3），不再用界面 WPM 猜。
  - 字符/单词间隔阈值 2.0 / 6.0 单位，从“元素结束时刻”起算静音。
  - `PushElement` / `Tick` / `Reset` / `SetWpm`，纯逻辑、时间外部注入，可单测。
- `MainWindow.xaml.cs` 重写
  - 串口解析从 UI 线程移到 `DataReceived` 线程，事件时间戳在接收处取，避免 UI 卡顿破坏解码时序。
  - 解码定时器改为 `System.Threading.Timer`（20ms），心跳改为线程池 `Timer`（1s）。
  - 关闭窗口改为“先取消 + 异步 BYE 交接（等 BYE,BUZZER 确认，超时 900ms）+ 再关闭”。
  - 新增 `EmergencyHandoff()`，音频状态加锁，`_handshakeSource` 改用局部变量避免竞态。
- `App.xaml.cs`：`OnSessionEnding` / `DispatcherUnhandledException` / `ProcessExit` 均调用 `EmergencyHandoff()`。

### 已验证
- `dotnet build` 0 警告 0 错误。
- 临时控制台工程跑解码器时序测试：CQ / CQ CQ / SOS / HELLO / 5·25·15 WPM / ±25ms 抖动 / 字符间隔 4 单位 / 数字 全部通过。

### 实板发现（重要）
- COM7 上跑的固件**不是**仓库 HEAD 版本：它对每个收到的字节打印 `DBG_RX,<hex>` 和 `DBG_LINE,...`。
  该调试代码存在于历史提交 668337b / 884aa88，位于 `readSerialCommands()` 内，用 `Serial.print` 逐字节输出。
- 关闭串口后 COM7 无法再次打开（Windows 报“设备没有发挥作用”），必须物理 RST/重新插拔。
  与“关软件后硬件静音、只能 RST”的现象一致：调试输出把 USB CDC 写满 → `Serial.println` 阻塞 → `loop()` 停摆 → 6 秒失联回退永远不执行；同时 CDC 端点被拖死。
- 结论：问题 A 的首要疑因是板上那份带调试打印的固件，而不是仓库里的 HEAD 固件（HEAD 无 DBG 输出）。

### 待办
- 用户 RST 后，用 HEAD 固件复测“关软件 / 强杀进程 / 拔 USB”三种场景。
- 若 HEAD 仍复现，需要改固件（租约刷新 + 每周期重算输出），需用户授权。

## 收尾：音频设备选择 + 发布 + README

### 新增 AudioOutput.cs
- 音频从 PlaySound 换成 winmm `waveOut`，因为 PlaySound 只能走默认设备。
- 设备列表第 0 项是「跟随系统」（WAVE_MAPPER）；静音 4 秒释放设备，
  下次发声重新 open，WAVE_MAPPER 会重新解析默认设备 → 插拔耳机不用重启。
- 自管 WAVEHDR + 缓冲区（AllocHGlobal / PrepareHeader / Write / Reset），
  元素音带 3ms 淡入淡出；直键用 WHDR_BEGINLOOP/ENDLOOP 无缝循环 + Reset 停止。
- 打不开指定设备时自动退回 WAVE_MAPPER 并写日志。

`WAVEOUTCAPS` 里 **szPname 在 dwSupport 之前**（16 字节头 + 64 字节名字 + 4 字节 dwSupport = 84）。
按头文件直觉写成 dwSupport 在前，读出来的设备名会整体左移 4 字节，变成 "igh Definition Audio Devi"。
MME 名字上限 32 字符，接近上限时补「…」。

### 界面调整
- 画布 1200×760 → 1200×800，顶栏 64 → 56，给「输出设备」留一行。
- 声音输出卡片：分段 → 输出设备 → 音调 → 音量。

## 追加：暗色模式、电码表、修窗口白边

### 暗色模式（跟随系统，无开关）
- 新增 `Themes/Light.xaml` / `Themes/Dark.xaml`，键名完全一致；
  语义不变：Ink=主文字，Paper=卡片，Surface=画布/凹槽，OnInk=墨黑底上的字（暗色下变深）。
- App.xaml 里所有刷子引用从 StaticResource 改成 **DynamicResource**，换主题时不重建控件即可整页刷新。
- 判断：注册表 `HKCU\...\Themes\Personalize\AppsUseLightTheme`（0=深色）。
- 实时跟随：窗口挂 `WM_SETTINGCHANGE`（lParam = "ImmersiveColorSet"）+
  `SystemEvents.UserPreferenceChanged`，两条路都走 `App.RefreshTheme()`。
- C# 里设置的动态颜色改用 `SetResourceReference`，否则换主题后仍是旧刷子。

### 坑
- **ListBox / ListBoxItem 的 Foreground 会退化成控件默认黑色**（Control.Foreground 默认值不继承），
  暗色下日志直接看不见。自定义样式必须显式设 Foreground。

### 电码表
- `MorseTable.Entries` 改成有序数组，字典由它生成，界面的顺序和映射不会再走偏。
- 入口在抄收卡片右上角（GhostButton 小按钮），浮层 5 列 × 11 行，点一行按当前 WPM 播放，Esc/点遮罩关闭。

### 窗口顶部白边（用户的第 3 个问题）
- 根因：`WindowStyle=None` + `ResizeMode=CanResize` 时，DWM 仍保留约 7px 非客户区。
  实测客户区是 1186×786（窗口 1200×800），顶部那条白边就是这块。
- 修复：加 `<WindowChrome CaptionHeight=0 ResizeBorderThickness=6 GlassFrameThickness=0>`。
  修完客户区正好 1200×800，白边消失；拖动仍由自己处理，边缘仍可缩放。

### 测试与设备状态（重要）
- 上一轮 uitest 直接 `proc.Kill()`，会把 ESP32 的 CDC 端点拖死 → **COM7 现在打不开，
  需要按 RST**。当前 PowerShell 不是管理员，`Disable-PnpDevice`/`pnputil` 都做不了。
- 已把 uitest 改成 `WindowPattern.Close()` 正常关闭，以后不会再拖死。
- 设备无关的界面自测：客户区 1200×800、电码表入口、展开 70 个按钮、Esc 关闭，4 项全过。
- 系统当前就是深色（AppsUseLightTheme=0），所以软件启动即为暗色。

## 又一轮：窗口样式回退、设置面板、偏好持久化

### 窗口圆角与原生动画（用户反馈改坏了）
- 根因：`WindowStyle="None"` + `WindowChrome(GlassFrameThickness=0)` 让窗口变成无边框 popup，
  DWM 不再给圆角（Win11）也不再跑最小化/最大化动画。
- 修复：`WindowStyle="SingleBorderWindow"` + WindowChrome 保留（CaptionHeight=0 仍自绘标题栏）。
  再补一句 `DwmSetWindowAttribute(hwnd, 33 /*CORNER_PREFERENCE*/, 2 /*ROUND*/)` 显式要圆角。
- 同时去掉自己设 MaxHeight/MaxWidth 的最大化 hack，交回系统；实测最大化后窗口 1048 / 屏幕 1080，任务栏没被盖。
- 验证手段：截图抓「窗口 + 24px 外边距」，再打印左上角像素 ASCII 图，能看到弧形收边。

### 设置面板
- 顶栏齿轮（自绘 sliders 图标：两条线 + 两个圆环，Fill=Transparent，18→19px 更清楚）。
- 浮层里「外观」三选一：跟随系统 / 浅色 / 深色；改完立即生效并写盘。
- 按钮要加 `AutomationProperties.Name="设置"` 和 `x:Name`，否则 UI 自动化找不到。

### 偏好持久化
- `AppSettings.cs`：`%AppData%\CWTrainer\settings.json`，存 Theme / ToneHz / Volume。
- 启动时先读设置再决定主题（在 OnStartup 里、主窗口创建之前）。
- 音调、音量改动 600ms 防抖后写盘。

### 又踩的坑
- 枚举叫 `ThemeMode` 会和 .NET 10 WPF 新增的 `Application.ThemeMode` 属性冲突 → 改名 `AppTheme`。
- **MainWindow.xaml 里的颜色之前还是 StaticResource**，运行时换主题不会刷新；
  全部改成 DynamicResource 后，设置里切主题才真正整页生效。

### 测试
- dist 发布版：界面 6 项（含拖动窗口位移 60px、最大化不盖任务栏）、设置 4 项、记忆 2 项，全过。
